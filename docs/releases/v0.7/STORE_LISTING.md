## Single purpose

> A local-first study companion that organizes courses, deadlines, progress and private practice from Moodle course sites the student chooses to enable.

Every shipped feature supports that purpose: read-only course capture, Today and Tasks organization, reminders and calendar export, local flashcards and practice, study notes, focus sessions, appearance preferences, local motivation and optional AI study that summarizes or builds practice from a course PDF the student picks.

## Permission justifications

Paste these into the corresponding dashboard fields.

### `storage`

Moodlens saves the student's language, theme, enabled-site registry, dashboard preferences, bounded course/task snapshots, reminder choices, local study progress and the chosen AI provider and model name in Chrome extension storage. An AI API key, when the student enters one, is kept only in `chrome.storage.session` until the browser closes or the student presses Forget key. The data is used only for the visible study-companion features and is not sent to the developer.

### `sidePanel`

Moodlens's primary interface is a Chrome side panel so students can view their study dashboard beside an open course without replacing or modifying the Moodle page.

### `scripting`

After the student explicitly enables one Moodle origin, Moodlens registers its packaged read-only course reader and, when selected, its packaged appearance stylesheet for that origin. It never injects remote code.

### `alarms`

Moodlens uses local Chrome alarms to recreate opted-in deadline reminders after browser restart and to finish a student-started focus session. Alarms never poll Moodle or contact a server.

### Optional `notifications`

Requested only when the student turns reminders on. It displays local deadline reminders generated from the student's stored task list. The feature remains off if permission is declined.

### Optional host access `https://*/*`

Moodle can be hosted on many HTTPS domains, so the manifest declares a broad optional pattern. Moodlens requests access to only one student-entered Moodle origin after the student clicks Enable and Chrome shows its permission prompt. The same optional pattern covers the one AI provider origin the student chooses (see below). There are no static host permissions, and removing the site revokes access.

### Optional AI provider hosts

No provider host is declared statically. When the student presses Continue on the AI consent screen, Moodlens asks Chrome for access to exactly one fixed provider origin (for example `https://generativelanguage.googleapis.com/*`) under the optional `https://*/*` pattern. Declining sends nothing. The request carries only the excerpts and question shown on the consent screen, with the student's own key in a header; credentials and referrer are omitted.

## Privacy practices dashboard

Answer from the shipped behavior, including local processing and the optional AI study transfer:

| Dashboard data type | Answer | Explanation |
|---|---|---|
| Personally identifiable information | No | Moodlens has no account and does not intentionally read names, email addresses or student identifiers. |
| Health information | No | Not used. |
| Financial and payment information | No | Not used. |
| Authentication information | Yes, handled transiently | The content script reads a Moodle `sesskey` from the open enabled page for one same-site read-only request. It is never stored, messaged, logged or sent to the developer. Passwords and cookies are never read. A student-entered AI API key is kept in session storage and sent only to the provider the student chose, as a request header. |
| Personal communications | No | Messages and forum content are not read. |
| Location | No | Not used. |
| Web history / browsing activity | Yes, limited | Enabled Moodle origins and course/activity URLs are handled only to provide navigation and the visible course/task features. They stay local. |
| Website content | Yes | Bounded course names, activities, completion states, deadlines and finished-review practice fields are read from enabled Moodle sites and stored locally for the disclosed features. For AI study, text excerpts from a PDF the student picks, plus the student's question, are sent to the student-chosen AI provider only after the student reviews the exact text and presses Continue. |
| User activity | Yes, limited | Local study actions such as card reviews, focus sessions, notes and dashboard choices are stored only to provide those features. |

Data usage declarations:

- Not sold to third parties.
- Not used or transferred for purposes unrelated to Moodlens's single purpose.
- Not used or transferred to determine creditworthiness or for lending.
- Not used for personalized advertising.
- Transferred to a third party only for the user-facing AI study feature: the excerpts the student approved go to the AI provider the student chose, with the student's own key. Moodlens does not receive a copy.
- No humans at Moodlens read user data; Moodlens has no developer backend. A user may voluntarily include sanitized information in a GitHub issue.
- All network access is HTTPS and limited to the student-selected Moodle origin and, after consent, the one student-chosen AI provider origin.

Limited Use certification statement:

> Moodlens's use of information received through Chrome APIs adheres to the Chrome Web Store User Data Policy, including the Limited Use requirements. Moodlens uses user data only to provide or improve its disclosed study-companion purpose and does not sell it, use it for advertising or credit decisions, or permit human access except with explicit user consent or when required for security or law.
